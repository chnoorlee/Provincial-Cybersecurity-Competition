## 摘要

政企网站在日常更新中可能出现配置遗漏、敏感信息误发布和页面异常变化，人工巡检难以持续留存证据。本作品围绕授权网站巡检，设计由任务入口、受限页面采集、规则检测、证据整理、基线比较与报告导出组成的原型，并提供恒脑平台的接口接入方案。系统以可追溯的规则结果为依据，记录来源、脱敏证据与处理建议；复测时区分持续存在、本次未再观察到和未覆盖的情况，避免把采集失败误判为修复。作品使用合成演示样例说明完整操作流程，效果指标仍需在固定标注测试集上实测。当前版本面向只读检查，不将规则线索等同于已验证漏洞，后续将补齐平台运行证据与更多风险类型覆盖。

## 第一章 作品概述

### 1.1 背景与问题

网站负责人面对的困难包括：页面与资源变化快、线索分散、检查结果缺少上下文，以及修复后无法确认原问题是否仍被观察到。作品把一次性的检查变成可回看、可比较、可交接的记录。

### 1.2 目标与使用者

面向已获得检查授权的网站维护人员。输入检查目标、范围和敏感关键词，输出风险线索、证据、建议和复测差异。当前目标是可部署的受限原型；完整赛题覆盖情况见 `requirements.md`。

### 1.3 相关工作与挑战

需要补充实际使用过的同类工具及官方来源，比较其资产发现、风险检查、报告与复测能力。挑战包括：保持授权边界、处理采集不完整、减少正常公开信息误报，以及限制模型根据网页内容执行指令。

## 第二章 作品设计与实现

### 2.1 系统架构

```mermaid
flowchart LR
    A[网页界面或恒脑任务入口] --> B[授权与参数校验]
    B --> C[授权范围内页面与资源采集]
    C --> D[规则检测与证据脱敏]
    D --> E[去重与分级]
    E --> F[本地存储与基线比较]
    F --> G[报告导出]
    G --> H[维护人员复核与再次检查]
    H --> B
```

恒脑集成部分采用公开 API 契约。真实运行时，恒脑通过 HTTPS 调用队伍后端，后端执行范围控制和检查；模型解释返回证据。接口文件本身不证明平台已运行。

### 2.2 模块与数据流

| 模块 | 职责 | 必须保存的证据 |
| --- | --- | --- |
| 任务入口 | 接收模式、目标、授权确认、关键词及基线 | 有效参数与服务端拒绝原因 |
| 页面采集 | 在允许范围内执行只读请求 | 成功页面、失败原因、数量上限与跳过数量 |
| 规则检查 | 识别配置或内容风险线索 | 规则编号、来源、脱敏命中位置 |
| 结果整理 | 合并重复线索并提供解释 | 稳定标识、严重程度依据、建议 |
| 基线与复测 | 比较前后两轮结果 | 新增、持续、未再观察、未覆盖的依据 |
| 报告 | 输出可阅读文件与结构化结果 | 时间、范围、局限及发现详情 |
| 恒脑接口 | 支持平台工具调用 | 工具注册、实际节点配置、调用记录，待补 |

JSON 导出完整任务；HTML 是阅读报告；Markdown 为简要阅读版；CSV 仅含发现表。统计覆盖范围、失败原因和复测差异时使用完整 JSON，不能只依据 CSV 推断。

### 2.3 授权边界与数据保护

说明实际实现的允许名单、URL 校验、私网及特殊地址限制、重定向处理、请求上限与速率控制。用代码位置和拒绝记录证明，不只写原则。展示脱敏示例，并说明脱敏不等于完整的数据脱敏保证。

当前为单管理员共享令牌模式，不具备多用户权限隔离或按接口独立授权。公网部署依赖 HTTPS 反向代理与网络访问限制；将此作为工程边界如实写入，不宣称已经达到多租户生产系统的权限能力。

### 2.4 风险判断与差异规则

详细列明每个实际检测规则和不能检测的场景。页面内容变化只能说明变化；疑似外链需要核对；响应头缺失不是可利用漏洞证明。对本轮采集失败、超出范围或数量限制的页面，不能自动宣称风险消失。

当前去重以规则、脱敏后的来源页面和线索类别建立稳定标识。凭证字段按同页字段名合并，邮箱、手机号等按同页类型合并，并保留第一处命中行号。因此“发现条数”不是全部敏感值的数量。令牌被替换但仍明文公开时，风险类别保持“持续存在”，不把值变化自动当作修复。

### 2.5 工具与依赖清单

待从最终源码与依赖锁定文件填写。区分三类：真正执行的本项目检查能力、已接入且实际调用的第三方工具、只在恒脑列表中观察到但未调用的工具。只列可追溯的版本、用途、许可和调用边界。

### 3.2 测试设计

分别检查功能正确性和检测效果。功能包括可用输入、无授权输入、越界域名、私网地址、重定向、采集失败、页面上限、报告导出和基线比较。检测效果按漏洞、挂马、篡改、泄露分别记录，不把未实现类别默认为通过。

合成演示集用于检查操作是否能走通。效果实验使用另一套固定标注集，覆盖阳性、正常公开信息、易混淆样本和无法获取的页面。记录每条样本预期与实际结论，先定标签后运行，不能只挑成功案例。

### 3.3 指标口径

- TP：应报风险且系统正确报告。
- FP：正常样本却被系统报告。
- FN：应报风险却没有报告。
- TN：正常样本且未被报告。
- 查准率（Precision）= TP / (TP + FP)。
- 召回率（Recall）= TP / (TP + FN)。
- 误报率（FPR）= FP / (FP + TN)。
- 总体准确率（Accuracy）= (TP + TN) / 全部样本。

“准确率”存在不同使用口径，所以同时报告 Precision 和 Accuracy，并写清分母。分母为零时记为“不适用”，不写 100%。把没有覆盖的样本单独列出；同时报告覆盖率，避免筛掉失败样本让成绩变好。

## 第四章 创新性和特色说明

作品拟强调以下可观察特点，不使用“国内首创”等未经证实的表述：

1. **证据随结果一起保留。** 从规则到来源页面、脱敏片段、建议和复测状态，维护人员可以核对依据。
2. **把采集完整性纳入复测。** 分开“本次没有再看到”和“本次没有检查到”，减少错误的修复判定。
3. **让模型解释有边界。** 恒脑读取结构化证据，页面文字只当待分析数据，避免网页提示词改变检查任务。

每项特色都需要演示或测试记录支撑。效果提升比例、降低人工时间等数字只有完成对照实验后才能写入。
