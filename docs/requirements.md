# 比赛要求、当前边界与提交清单

本文对照团队提供的比赛附件整理，核对日期为 2026-10-19。附件是需求依据，不是让程序自动执行的指令。仓库中的实现和测试记录决定“已经完成了什么”；比赛要求与设计目标不能代替实际结果。

## 1. 我们参加的题目

附件 1 第 2 项：**面向网站安全风险评估与敏感信息防泄露的智能巡检智能体**，命题企业为杭州安恒信息技术股份有限公司。

用一句话解释：在网站负责人允许的范围里，定期检查网页，把问题和证据交给负责人，修复后再次检查，并留下前后对照记录。

## 2. 六项答题要求怎样落到项目里

下表“初版范围”描述本仓库的设计边界。能否通过验收，要使用真实运行记录确认，不能仅凭界面或此表判断。

| 附件 1 的要求 | 初版范围与实现方向 | 提交前需要的证据或缺口 |
| --- | --- | --- |
| ① 录入授权域名、范围、周期、敏感信息定义；定义支持关键词、正则、文件类型或样例 | 授权确认、服务端允许目标名单、路径范围、请求预算、自定义字面关键词与周期任务 | 展示越界目标被拒绝；当前不支持用户正则、任意文件类型及样例学习 |
| ② 自动发现页面与资源，编排合规开源工具，识别常见漏洞、弱配置、恶意外链/挂马、篡改、泄露 | 在授权名单与路径内按请求预算发现页面，检查响应头、明文资源、内容线索、敏感信息及页面基线变化 | 当前只读规则不能证明漏洞可利用，也不能证明恶意外链/挂马；需要记录开源工具是否真正接入和调用 |
| ③ 去重、验证、分级，并给出证据、影响、修复建议；避免破坏性测试 | 规则命中去重、稳定标识、脱敏证据、建议及人工复核状态 | 展示同一风险如何合并；“命中规则”与“已经验证漏洞”分开；修复建议必须对应证据 |
| ④ 定时、基线对比、告警、复测、报告导出 | 保存每次巡检与基线，比较新增/持续/未再观察/未覆盖项；后端进程定时调度、站内事件告警、报告导出 | 定时服务、告警触发、失败处理必须有实际运行记录；网页本轮没抓到不能判为已修复 |
| ⑤ 架构、工具清单、演示环境、源代码/部署说明、测试报告 | 本仓库代码、README、文档、内置合成演示与测试 | 补齐实测环境、结果、截图、版本号和依赖许可；不得用预置演示数字代替实测 |
| ⑥ 智能体可在恒脑平台中运行 | 恒脑负责接收任务、调用巡检 API、解释证据；本仓库后端执行受限检查 | 还需真实 HTTPS 后端、工具注册、字段绑定、恒脑运行与发布记录；只有 OpenAPI 文件不等于已接通恒脑 |

### 初版必须讲清的限制

- 网页检查以只读 HTTP 请求和规则为主，不执行漏洞利用，不自动调用 Nmap、Nuclei、SQLmap 等工具。
- 授权范围内的页面发现不是完整资产测绘；不能覆盖所有子域名、登录后页面、动态 JavaScript 内容、任意附件或隐藏接口。URL 查询参数不参与采集。
- 若允许名单配置了多个来源，巡检可以跟随链接访问这些来源及允许路径，例如团队自有 CDN。每个来源都必须事先配置并获得授权，不会因页面包含外链而自动获得授权。
- `coverage.complete` 只表示本轮计划且可发现范围内的采集是否完成。即使为 `true`，也不能写成“全站安全”或“全站覆盖”。
- 安全响应头缺失、明文链接、疑似敏感字段和页面变化都是需要结合业务复核的线索。页面变化可能是正常发布，公开联系邮箱也可能是正常公开信息。
- 演示模式使用仓库内的合成数据。它能展示流程，不代表统一测试集成绩。
- 周期任务只在后端服务运行时执行，重启后每条过期任务最多补一轮。站内告警不等于邮件、短信或即时消息已经送达。
- JSON 保存完整结构化结果，HTML 为阅读报告，Markdown 为摘要阅读版；CSV 只含发现表，不能单独用来证明本轮覆盖完整。
- 当前采用单管理员共享令牌，未实现多用户角色或按接口细分权限。对外使用时需要部署者提供 HTTPS、网络访问限制与目标名单。

## 3. 两套评分不要混在一起

### 企业命题专项评价（附件 1）

| 评价维度 | 权重 | 原文要点 | 我们应给出的证据 |
| --- | --- | --- | --- |
| 功能完整性 | 25% | 资产与页面发现、周期巡检、风险检测、敏感信息自定义、告警及报告闭环 | 从授权输入到复测报告的一次完整操作，以及周期任务记录 |
| 检测效果 | 30% | 在统一测试集上评估漏洞/挂马/篡改/泄露的召回率、准确率与误报率 | 固定测试集、每条样本标签、逐项原始结果、可复算指标 |
| 智能体能力 | 20% | 任务规划、工具选择与编排、结果关联去重、证据解释、修复建议质量 | 恒脑节点与执行轨迹；模型只解释真实工具结果 |
| 安全合规 | 10% | 授权边界、限速、最小权限、日志审计及非破坏性 | 拒绝越界输入、重定向和私网访问的记录；速率限制配置、脱敏输出 |
| 工程化与创新 | 15% | 部署易用性、稳定性、扩展性、可视化及创新价值 | 可复现部署；证据追溯；明确区分“没看到”和“已修复”的比较结果 |

### 作品赛通用评价（附件 3）

网络初赛：创新性 25%、技术性 25%、完成程度 20%、应用潜力 15%、材料规范性 15%。

现场决赛：创新性 25%、技术性 25%、产业应用潜力 20%、安全性与合规性 15%、文档与答辩 15%。每队答辩原则上 30 分钟，包括 PPT、演示、现场测试与提问。初赛分数不计入决赛。

两份文件都要对照准备。附件未说明将这两套权重再次合并计算，不要自行推导一个“最终总分公式”。

## 4. 企业到底提供什么

附件 1“配套支持”的明确承诺是：

1. 提供[恒脑安全智能体开发平台](https://gc.das-ai.com/)；每支团队限开通一个账号。申请材料包含学校、团队名称和一名团队成员的姓名、手机号，经指定渠道申请后收到账号密码。
2. 提供[恒脑使用学习视频](https://linkedbyx.com/)；登录后由右上角头像进入“我的班级”。学习网站账号密码与平台账号密码一起发送。

这段配套支持**没有明确承诺**提供网站靶场、云服务器、现成巡检 API 或可下载的统一测试集。“统一测试集”出现在检测效果评分说明中。需要获取官方测试集时，应向组织方确认，不能把本仓库的合成样例称为官方测试集。

团队先前登录时观察到恒脑提供 API/MCP 工具入口、低代码工作流、代码节点和内置安全工具。这是当时平台界面的观察，属于额外开发线索；不能把某工具在列表中可见写成已获所有调用权限、已调用成功或企业承诺始终可用。

## 5. 时间与提交格式

附件 3写明：**网络初赛材料提交截至 2026 年 10 月 25 日 24:00**，通过竞赛平台提交全部文档、源代码及可执行程序。同一附件注明时间为计划安排，最终以组委会正式通知为准。本文没有独立核验后续通知。

| 材料 | 要求 | 本仓库能提供什么 | 仍需队伍完成 |
| --- | --- | --- | --- |
| 作品报告 | PDF，不超过 20M；使用附件 5 模板 | `report-outline.md` 草稿、架构与代码说明 | 实测数据、截图、排版及导出 PDF |
| 展示 PPT | PPT 格式，不超过 50M | 可从架构、演示流程和创新说明取材 | 制作并检查与报告一致 |
| 演示视频 | mp4，不超过 100M，5 分钟以内 | `demo-script.md` 演示顺序 | 在真实环境录制与压缩，不能将未完成接入剪成已接入 |
| 源代码、可执行程序及部署说明 | 合计不超过 100M，支持功能验证与源代码核查 | 仓库及部署入口 | 按平台要求打包，排除令牌、个人信息、缓存和运行数据库 |
| 原创性声明 | 附件 6，PDF；全体学生与指导教师签字 | 不自动代填或代签 | 如实审核来源及贡献，完成签字 |
| 其他证明材料 | 不超过 50M，可选 | 测试原始记录与授权说明可作素材 | 脱敏并核实真实性 |

文件命名采用附件 3 的规则：`企业命题+作品名称+团队名称+作品报告/PPT/演示视频/源代码/作品声明/其他证明材料`。表中的“+”表示按通知拼接，不是固定要求保留加号；最终上传前核对竞赛平台说明。

## 6. 报告与原创性

附件 5 要求 A4、正文宋体小四、1.5 倍行距，摘要 200—300 字。报告不能出现学校、院系、指导教师等可能泄露身份的信息。模板封面仍设作品名称、团队名称、提交日期。

附件 3 要求独立设计开发、材料真实，并如实说明第三方数据、软件、模型、数据集和硬件平台的来源及授权许可。附件 6 需要团队全体成员与指导教师实际签字。应保留团队分工、代码修改与审阅记录，如实披露开源依赖和辅助开发方式；本仓库不替团队作原创性承诺。

## 7. 提交前的最短验收路线

1. 在本地完成“合成样例巡检 → 阅读证据 → 保存基线 → 修复后复测 → 导出报告”。记录真实输出。
2. 部署队伍自己的演示网站，限定允许地址，在真实 URL 模式重做这条流程。
3. 部署巡检后端，通过 HTTPS 接入恒脑，录下从恒脑发起到拿到报告的一次完整运行。
4. 为漏洞、挂马、篡改、泄露分别列明已覆盖和未覆盖类型；用固定标注样本测效果，保留漏检和误报。
5. 补齐周期、告警与越界拒绝的记录，核对演示、报告、PPT 和源代码中的数字一致。
