## 如果展示真实网站

“合成样例”的说法替换为准确的目标说明，例如“我们部署的演示站点”。不要展示未经允许的网站。选择一个页面少、内容稳定的演示站点，先让评委看到清晰的闭环，再解释扩展能力。

GitHub Pages 可以承载静态演示页面。它不能运行本项目的 Python 巡检后端，也不能模拟真实数据库注入、服务器命令执行等漏洞。录像时不要把静态假线索称为已成功利用的漏洞。

## 答辩时可能被问到的三个问题

**为什么用了大模型？** 检查结果应由工具与规则产生。大模型负责把需求转成允许范围内的计划、组织调用、解释已有证据。要展示实际恒脑调用记录，不能只靠提示词截图证明智能体能力。

**“没有再发现”是否代表修好了？** 只有同一证据范围确实重新检查过，才可以说本次未再观察到；是否修复仍需要结合修改记录和人工确认。采集失败或超出页数上限时，必须保留“未覆盖”。

**效果有多好？** 给出实际标注测试集、版本和可复算指标。未完成对应实验时，应回答“尚未测量”，不能给估计百分比。
